# 1. ابدأ بتحليل المشروع الحالي

قبل أن تعدل أي شيء:

1. افحص جميع ملفات المشروع الحالية.
2. افهم الـHTML والـCSS والـJavaScript الحالي.
3. اكتشف جميع الصفحات والـfeatures الموجودة.
4. اكتشف الـAPIs المستخدمة حاليًا.
5. اكتشف لماذا الـAPI أو البيانات لا تظهر حاليًا.
6. افحص Network requests وAPI endpoints وresponse formats.
7. افحص أي errors أو deprecated endpoints.
8. لا تحذف أي feature موجودة بدون سبب.
9. احتفظ بالمحتوى الموجود حاليًا قدر الإمكان.
10. إذا كان الـAPI القديم غير موثوق أو متوقف، لا تجعل التطبيق يعتمد عليه بشكل كامل.

بعد التحليل، نفّذ إعادة البناء.

# 3. Islamic Content Reliability — مهم جدًا

هذه نقطة أساسية.

لا أريد أن يصبح التطبيق فارغًا إذا توقفت API.

صمّم Data Layer احترافي:

API → Cache → Local fallback

بحيث:

1. حاول الحصول على البيانات من API.
2. إذا نجح الطلب، اعرض البيانات واحفظ نسخة مناسبة في cache.
3. إذا فشل الـAPI:

   * استخدم cached data.
4. إذا لم توجد cached data:

   * استخدم local static data عند الإمكان.
5. اعرض للمستخدم حالة واضحة إذا كانت البيانات غير متاحة.

لا تجعل UI يعرف تفاصيل الـAPI.

استخدم services مثل:

quranService
hadithService
duaService
azkarService
prayerService

واجعل التعامل مع API منفصلًا عن الـcomponents.

# 22. Security

طبّق security best practices.

خصوصًا:

* لا تضع API secrets داخل frontend
* لا تضع private keys في Git
* استخدم environment variables
* Validate external API responses
* Sanitize أي HTML يأتي من مصادر خارجية
* لا تستخدم dangerouslySetInnerHTML إلا عند الضرورة القصوى وبعد sanitization
* لا تثق في user input
* لا expose sensitive configuration
* لا تستخدم eval
* لا تستخدم unsafe dynamic code execution
* أضف security headers إن كان الـdeployment يسمح بذلك

إذا كان هناك external API:
اجعل الـAPI layer قابلة للتغيير بسهولة.
